# Linear 的疯狂实验：一个 bug 都不放过的 175 天

2023年之前，Linear 和大多数公司一样，有个不断膨胀的 bug 积压池。工程师们修不完，用户们接着抱怨。

但联合创始人 Tuomas Artman 遇到的一件事彻底改变了这一切。

## 一个 bug 改变了产品哲学

五年前，Artman 在一个热门消费应用中发现了 bug并报告给团队。两年后——是的，整整两年——他才看到它被修复。

> "数百万人因为这个 bug 忍受了这么多年。如果公司最终要修复它，为什么不马上修？"

这就是 Linear 零 bug 政策的起点。

## 三个月只修 bug

2023年，Linear 做出了一个激进决定：清空所有积压 bug。他们有 **175 个** open bugs。

他们停掉了所有其他项目，整整三周，全公司只做一件事——修 bug。

没有新功能，没有产品迭代。只有 bug。

## 48 小时生死线

清空积压只是第一步。为了维持零 bug，Linear 设定了严格的 SLA：

- **高优先级 bug**：48 小时内修复
- **低优先级 bug**：7 天内修复

每个被分配的 bug，工程师必须选择：要么标记"不修"（如果真的无关紧要），要么承诺修复。**没有"稍后处理"这个选项。**

> "修一个 bug 花的精力是一样的，早修还能让用户少受罪。"

## 魔法般的体验

这个政策带来了意想不到的副作用：当用户报告一个 bug，第二天（甚至当天）就发现它被修复了。

2024年10月，一位用户在下午报告了 Linear 编辑器中的段落换行问题——**当天就被修复**。

这种"即时满足"让用户变成了自来水。
