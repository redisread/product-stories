# Linear 的实时协作突破：如何在毫秒级同步数千个并发编辑

## 2021年初，Linear 的用户增长遇到了一个致命瓶颈。

团队收到了越来越多的投诉：当多个用户同时编辑同一个 issue 时，系统会崩溃或丢失数据。对于一个标榜"流畅体验"的工具来说，这简直是灾难。更糟糕的是，传统的解决方案要么太慢，要么太复杂。

## 转折点出现在一次凌晨3点的紧急会议中。

CTO Tuomas Artman 盯着监控面板上不断攀升的错误率，突然说："我们不能用现有的实时数据库方案。我们必须自己造轮子。" 这个决定让所有人都倒吸一口冷气——从零开始构建实时同步引擎意味着至少6个月的开发时间，而竞争对手正在快速追赶。

## 团队立即投入了这场技术攻坚战。

他们放弃了传统的 Operational Transform（操作转换）算法，转而采用 Conflict-free Replicated Data Types（CRDTs）——一种分布式系统的前沿技术。但 CRDTs 在实际应用中存在严重的性能问题，特别是在处理复杂的嵌套数据结构时。

Linear 的工程师们进行了数百次实验，最终发明了一种混合算法：将 CRDTs 用于元数据同步，而用优化的操作转换处理富文本内容。他们还构建了一个独特的"乐观更新"机制，让用户在本地立即看到更改，同时在后台异步同步到服务器。

为了测试这个系统，他们创建了一个极端场景：模拟1000个用户同时编辑同一个 issue，每个用户每秒进行10次操作。最初，系统在30秒内就崩溃了。经过三个月的迭代，他们终于实现了99.99%的成功率，延迟控制在200毫秒以内。

## 2021年9月，新实时引擎正式上线。

用户几乎立刻注意到了差异。编辑冲突消失了，协作变得丝般顺滑。更重要的是，这个技术突破成为了 Linear 的护城河——竞争对手需要数年才能复制这样的体验。

如今，Linear 的实时协作系统每天处理数百万次并发操作，成为现代 SaaS 应用的标杆。但团队知道，真正的胜利不是技术本身，而是它如何让全球的软件团队能够无缝协作。

> "最好的技术是用户感觉不到的技术。我们的目标不是展示技术有多酷，而是让用户忘记技术的存在。" — Tuomas Artman, Linear CTO
