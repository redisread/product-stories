# Supabase 的绝地反击：开源版 Firebase 的诞生

【开头】2020年初，Paul Copplestone 和 Ant Wilson 坐在伦敦的咖啡馆里，满脸沮丧。

【转折】他们刚刚在项目中使用了 Firebase，却发现其封闭生态和高昂成本让初创团队难以承受。更糟糕的是，当他们需要自定义功能时，Firebase 的黑盒架构让他们束手无策。"为什么没有一个开源的替代品？" Paul 问道。

【发展】两人都是经验丰富的开发者，Ant 曾在 Heroku 工作，对数据库和基础设施有深刻理解。他们意识到，现代应用开发的核心需求其实很明确：实时数据库、身份验证、存储和 API。而 PostgreSQL —— 这个被低估的开源数据库巨人 —— 已经内置了大部分这些功能。

他们开始疯狂编码。白天各自工作，晚上和周末全身心投入 Supabase。选择 PostgreSQL 而不是 MongoDB 或其他 NoSQL 数据库是个大胆的决定，但他们相信关系型数据库的力量被严重低估了。他们构建了一个自动化的系统，能将任何 PostgreSQL 表转换为 RESTful API 和实时 WebSocket 订阅。

早期版本简陋得可笑，但核心理念清晰：开发者应该拥有完全的数据控制权，不应该被供应商锁定。他们在 Hacker News 上发布了第一个版本，忐忑不安地等待反馈。

【高潮】出乎意料的是，帖子迅速登上首页，获得了数千个赞和数百条评论。开发者们对这个开源 Firebase 替代品表现出极大热情。GitHub 星星数在一周内突破 1000，一个月后达到 5000。YC 看到了潜力，邀请他们加入 2020 年夏季批次。疫情期间的远程工作浪潮更是推波助澜，Supabase 成为无数新创项目的首选后端。

【金句】> "我们不是要取代 Firebase，而是要给开发者选择的自由。" —— Paul Copplestone, Supabase 联合创始人
