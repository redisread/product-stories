# MongoDB 的诞生：从 DoubleClick 的数据库困境到 NoSQL 革命

2007年，Dwight Merriman 在 DoubleClick 面临一个令人沮丧的现实：传统的关系型数据库根本无法满足现代 Web 应用的需求。

## 转折点

作为 DoubleClick 的 CTO，Merriman 和他的团队每天都在与数据库扩展性问题搏斗。他们需要处理海量的广告点击数据，但 MySQL 和其他关系型数据库在面对这种规模的数据时表现糟糕。更糟糕的是，每次需要修改数据结构时，都要经历痛苦的迁移过程。Merriman 意识到，他们需要一种全新的方法——一个能轻松扩展、无需预定义模式的数据库。

## 发展历程

Merriman 找到了他在 DoubleClick 的同事 Eliot Horowitz，两人开始秘密开发一个新项目。他们想要创建一个文档型数据库，能够自然地存储 JSON 格式的数据，就像应用程序中使用的对象一样。Kevin Ryan（DoubleClick 的创始人）也加入了这个项目，提供了种子资金。

他们将这个项目命名为 "MongoDB" —— "Mongo" 来自 "humongous"（巨大的），反映了他们处理海量数据的雄心。开发团队花了近两年时间完善产品，期间经历了无数次的架构调整和性能优化。2009 年 2 月，MongoDB 1.0 正式发布，立即引起了开发者的关注。

MongoDB 的创新之处在于它摒弃了传统的表结构，采用灵活的文档模型。开发者可以随时添加新字段，无需复杂的 ALTER TABLE 语句。水平扩展也变得简单——通过分片（sharding）技术，MongoDB 可以轻松地在多台服务器上分布数据。

## 高潮时刻

MongoDB 的发布恰逢 Web 2.0 时代的爆发，无数初创公司正在寻找能够快速迭代、轻松扩展的数据库解决方案。MongoDB 迅速获得了市场认可，到 2010 年底，已经有数千个生产环境在使用 MongoDB。2017 年，MongoDB 成为首个成功 IPO 的数据库公司，市值超过 10 亿美元，证明了 NoSQL 数据库的巨大商业价值。

> "我们不是要取代关系型数据库，而是要解决它们无法解决的问题。" —— Dwight Merriman, MongoDB 联合创始人
