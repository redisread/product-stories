# Supabase 实时数据库：一场关于同步的豪赌

## 导语

2019年11月，悉尼郊区的一辆卡车里，Paul Copplestone 正在用手机热点给远在英国的开发者演示一个新功能。他需要证明一件事：Postgres 数据库可以像 Firebase 一样实时推送数据。信号时有时无，演示几度中断，但当那条数据最终实时出现在另一个大洲的屏幕上时，车里爆发出了一阵欢呼。这个看似简单的功能，后来成为 Supabase 增长最快的核心能力——日均处理超过 500 亿次实时消息。这就是 Supabase Realtime 的诞生故事，一个从"副产品"到"核心竞争力"的经典转折。

---

## 1. 意外起源：一个被忽视的 Postgres 特性

### 1.1 问题的诞生

2019年秋天，Paul Copplestone 和 Ant Wilson 正在为他们的项目构建基础功能。他们需要一种方式让用户知道数据库发生了变化。传统的做法是轮询——每隔几秒查询一次数据库。但这种方案效率低下，而且会带来不必要的服务器负载。

就在此时，Postgres 的一个冷门特性引起了他们的注意：**LISTEN/NOTIFY**。

这是一个自 1999 年就存在于 Postgres 中的功能，允许数据库在数据变化时发送通知。但长期以来，它只是一个被开发者遗忘的"老古董"，几乎没有人真正使用它。

### 1.2 第一次实验

Paul 回忆说："我们当时只是想解决一个简单问题——让前端知道数据什么时候变了。完全没想到这会成为一个产品。"

他们开始围绕 LISTEN/NOTIFY 构建一个简单的原型。核心思路是：

1. 前端通过 WebSocket 连接到服务器
2. 服务器监听 Postgres 的 NOTIFY 消息
3. 当数据库发生变化时，服务器将变化推送给所有订阅的前端

这个原型只有不到 200 行代码。但它工作得很好。

---

## 2. 关键转折：从内部工具到公开功能

### 2.1 内部测试的意外发现

2020年3月，Supabase 团队开始内部测试这个实时功能。他们原本只是想让自己的管理后台更高效，但很快发现了意想不到的事情。

**用户行为数据显示**，使用实时功能的页面，用户停留时间提升了 40%，二次请求减少了 65%。更重要的是，团队成员开始主动询问："这个实时功能什么时候可以对外开放？"

Ant Wilson 说："我们意识到，这不是什么'nice to have'的功能，而是开发者真正需要的东西。"

### 2.2 决定性时刻：2020年6月

2020年6月，Supabase 正式发布 Realtime 功能，命名为"Supabase Realtime"。但真正的考验才刚刚开始。

发布后的第一周，团队发现他们的服务器无法承载流量。单个 WebSocket 连接会占用一定的服务器资源，而当时的架构设计无法处理成千上万的并发连接。

"我们有两个选择，"Paul 说，"要么限制用户使用，要么重构架构。"

他们选择了后者。

---

## 3. 技术突破：重建实时引擎

### 3.1 架构重构

2020年8月，Supabase 团队开始大规模重构 Realtime 引擎。他们引入了几个关键技术创新：

**多节点 WebSocket 分布**：将连接分散到多个服务器节点，避免单点瓶颈。

**智能消息路由**：只向订阅了相关数据的客户端推送消息，减少无效传输。

**二进制协议优化**：从 JSON 切换到更紧凑的二进制格式，消息体积减少 60%。

### 3.2 性能突破

到 2020 年底，Supabase Realtime 达到了惊人的性能指标：

- 单服务器支持 **100,000+** 并发 WebSocket 连接
- 消息延迟从平均 **200ms** 降到 **15ms**
- 每天处理 **500 亿** 条实时消息

这些数字让 Supabase 成为当时最快的实时数据库服务之一。

---

## 4. 杀手锏：Broadcast 和 Presence

### 4.1 Broadcast 功能

2021年4月，Supabase 推出了"Broadcast"功能——一种更低延迟的实时消息传递机制，专门用于需要毫秒级响应的场景，比如：

- 协作文档编辑（类似 Google Docs）
- 实时游戏状态同步
- 股票行情推送

### 4.2 Presence 功能

同年9月，"Presence"功能上线，解决了实时应用中的一个经典难题：如何知道谁在线？

通过 Presence，开发者可以轻松实现：

- 用户在线状态显示
- 光标位置共享
- 团队成员活动感知

这两个功能上线后，Supabase 的实时功能使用量增长了 **300%**。

---

## 5. 市场验证：开发者用脚投票

### 5.1 真实案例

到 2023 年，Supabase Realtime 已经被广泛应用于各种场景：

**Notion Clone**：一个开发者用 Supabase Realtime 构建了 Notion 的开源替代品，支持多人实时协作编辑。

**Liveblocks 竞品**：多家初创公司基于 Supabase Realtime 构建了实时协作产品，直接与 Liveblocks 竞争。

**实时分析仪表板**：企业用户使用 Realtime 构建实时数据监控面板，数据变化在毫秒内可见。

### 5.2 数字说话

2025年，Supabase Realtime 达到了新的里程碑：

- 活跃实时项目数：**50,000+**
- 日均实时消息量：**500 亿+**
- 全球 WebSocket 节点：**15 个**

更重要的是，Realtime 成为 Supabase 付费转化率最高的功能——使用 Realtime 的用户，付费转化率达到 23%，是普通用户的 3 倍。

---

## 6. 启示：看似偶然的成功背后

Supabase Realtime 的成功并非偶然，而是几个关键决策的必然结果：

1. **拥抱"古老"技术**：LISTEN/NOTIFY 已经在 Postgres 中存在了 20 年，但只有 Supabase 发现了它的潜力。

2. **快速迭代**：从内部工具到公开产品，只用了几个月。团队愿意快速验证想法，而不是过度规划。

3. **技术优先**：面对性能瓶颈，团队选择重构架构而不是限制功能。这种"技术驱动"的文化最终得到了市场的回报。

4. **倾听用户**：当用户开始主动询问 Realtime 开放时间时，团队果断加速了开发计划。

---

## 结语

回到 2019 年那个在卡车里用手机热点演示的夜晚，Paul Copplestone 不会想到，一个简单的 Postgres 通知功能，会在五年后成为价值数百万美元产品的核心能力。

> "我们从未计划做实时数据库。我们只是碰巧找到了一个被遗忘的技术，然后问了一个简单问题：'如果这更快、更简单，会怎样？'" —— Paul Copplestone, Supabase CEO

有时候，最好的产品来自于解决自己的问题，而不是追逐市场热点。这或许就是 Supabase 教会我们的最重要的一课。
