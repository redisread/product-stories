# Next.js 与 Vercel 的意外协同：一个框架如何重塑部署平台

2016年的一个深夜，Guillermo Rauch 正在同时调试两个项目：他新创建的 React 框架 Next.js 和他的部署平台 Zeit（后来的 Vercel）。

## 意外发现

当时，Next.js 刚刚引入了服务器端渲染（SSR）功能，而 Zeit 平台专注于简化部署流程。Rauch 原本计划让这两个项目独立发展，但在一次测试中，他意外发现：**当 Next.js 应用部署到 Zeit 时，性能提升惊人**。

问题在于，传统的 SSR 需要完整的 Node.js 服务器，而 Zeit 的无服务器架构按请求计费。每次用户访问都会冷启动整个应用，导致首屏加载缓慢。Rauch 几乎要放弃这个组合。

## 突破时刻

就在准备分离两个项目时，团队中的工程师提出了一个疯狂的想法："**为什么不把 Next.js 编译成静态文件和边缘函数的混合体？**"

这个想法彻底改变了游戏规则。他们开始重构 Next.js，将页面预渲染为静态 HTML，同时将动态部分编译为轻量级的边缘函数。这样既保留了 SEO 友好的静态内容，又实现了真正的按需计算。

开发过程充满挑战。团队连续三周每天工作 16 小时，重写了核心编译器。有一次，整个构建系统崩溃，差点丢失一周的工作。但 Rauch 坚持认为这种深度集成是未来的方向。

## 完美协同

2017年初，这个新架构正式上线。结果令人震惊：**部署速度提升了 10 倍，成本降低了 80%**。开发者只需运行 `git push`，Vercel 就会自动检测 Next.js 项目，优化构建，然后在全球边缘网络上部署。

更神奇的是，这种深度集成创造了网络效应。Next.js 开发者自然选择 Vercel，而 Vercel 用户被 Next.js 的便利性吸引。到 2020 年，超过 **60% 的 Next.js 项目**都部署在 Vercel 上。

如今，这种框架与平台的深度协同已成为行业标准，催生了无数类似的组合，如 Remix + Cloudflare、SvelteKit + Netlify。

> "最好的工具不是那些功能最多的，而是那些能无缝协作的。框架和平台应该像齿轮一样咬合，而不是像胶水一样粘合。" —— Guillermo Rauch
