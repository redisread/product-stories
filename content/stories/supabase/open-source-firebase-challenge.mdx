# Supabase：当 Postgres 遇见开源野心

2020年初，Paul Copplestone 和 Ant Wilson 坐在悉尼的办公室里，看着自己的 Firebase 账单发愁。作为一家初创公司的技术团队，他们曾痴迷于 Firebase 的便捷——实时数据库、用户认证、一键部署。但客户越来越多，数据越来越乱，Firebase 的闭源特性让他们如坐针毡。

**"我们必须逃离这个平台。"** Paul 在一次深夜会议上拍板。

这个决定看似疯狂。Firebase 背靠 Google，拥有数百万开发者。而他们只是两个在悉尼创业的工程师，手头只有一个想法：用开源的 Postgres 做同样的事。彼时没有人知道，这个决定将在六个月后引爆开发者社区。

转机出现在迁移过程中。当团队开始用 Postgres 重写后端时，他们发现了一个被市场忽视的真相：**开发者爱 Postgres，但恨它的复杂**。于是，他们开始为 Postgres 包装一层 Firebase 式的简单界面——自动 API 生成、实时订阅、开箱即用的认证。产品雏形诞生时，团队成员才意识到，他们无意中做出了一个比原计划更有价值的东西。

2020年6月，Supabase 登陆 Hacker News，标题只有一句话："开源 Firebase 替代品"。短短 24 小时内，帖子收获 **2000 多个点赞**，评论挤满了类似的声音："终于有人做了我一直想做的事"。一个月后，Supabase 成功入选 **Y Combinator S20 批次**，成为那届最受关注的开源项目之一。

如今，Supabase 已服务超过 **50 万开发者**，融资超 **1.8 亿美元**。从悉尼的小办公室到全球开源数据库的领军者，Supabase 证明了：挑战巨头最好的方式，不是复制它们，而是反其道而行——**用开源的力量，重新定义游戏规则**。

> "我们不是为了打败 Firebase，而是要证明开源软件可以比专有软件更好。" —— Paul Copplestone
